A shared contract, from publisher to display.The Rust collector reads a normalized operations source and serves it with the display key. The ESP32 and browser demo use the same four-tab LVGL workspace. Native framework clients and an OTLP receiver are not bundled.

Start with one publisher.

Run the helper from a Glimdock source checkout. Copy the minimal fixture, map approved metadata from your actual lifecycle callbacks or read API, and atomically replace a private snapshot file. Keep unavailable fields null.

Open http://127.0.0.1:8784/?mode=file locally. The public website does not connect to that address. Your adapter supplies real timestamps and sequence values; serving a cached file must not make it fresh.

A small, explicit contract.

JSON SchemaOpenAPI
CollectionWhat it describes
sources / systemsProvenance, capabilities, TTL and scoped summaries
agentsIdentity, state, host, task, heartbeat and optional usage
tasks / eventsOwnership, lifecycle, parent tasks and concise metadata
channels / resourcesQueues, receipts, measured latency and lock ownership
limitsOriginal counts and explicit truncation
GET /v1/snapshotBounded normalized snapshot
GET /v1/capabilitiesSources, read-only status and size budget

POST and control requests return 405. The reference server’s mode query selects demo, file or configured hub data; another implementation can use its configured source directly.

Connect your display through the collector.

Add one optional agent_operations source to your private collector configuration. Use a source URL and separate key file, or an absolute snapshot_file path. A source failure leaves hardware collection available.

{
  "agent_operations": {
    "enabled": true,
    "url": "https://agents.example/v1/snapshot",
    "token_file": "/etc/glimdock/operations-source.key",
    "poll_interval_s": 5,
    "timeout_s": 3
  }
}

The ESP32 reads GET /api/v1/agent-operations at its existing collector address, with the same display reader key. The configuration/setup key does not grant reader access. GET and HEAD are supported; POST and execution controls are unavailable. An unconfigured or invalid source returns 503.

Source credentials stay in private files. HTTPS verifies certificates. Trusted remote HTTP requires the explicit allow_insecure_http: true option. The 48 KiB bound, scoped identities, original timestamps, null values and truncation rules apply to the production endpoint.

Keep the unknowns visible.

  • Null is unavailable. A measured zero is still zero.
  • Recency is not execution. An advisory heartbeat does not prove a model is running.
  • Ownership needs evidence. File-hub running work requires an active task and matching claim.
  • Freshness belongs to the source. Sample time, heartbeat time and HTTP receipt time are separate.
  • Usage is measured. Cost needs currency and provenance; progress needs a reported percentage.
  • Partial means partial. Preserve original totals and declare omitted records.

A2A state and OpenTelemetry token helpers are included as vocabulary mappings. They are not a full A2A client or OTLP receiver.

Monitor without exporting the conversation.

Include approved operational labels, states and measurements. Omit prompts, generated output, raw messages, transcripts, authorization notes, personal paths and secrets.

The reference server is loopback-only by default. A LAN bind needs a private read-token file; readers send an Authorization Bearer header. Use HTTPS or an authenticated reverse proxy remotely. Viewer keys and source credentials remain separate. The API cannot start, stop or approve work.

Verify the evidence and the interface.

Exercise missing and zero measurements, source expiry, unknown states, ownership races, duplicate IDs, truncation, oversized feeds and provider failures. Use synthetic fixtures, check the metadata allowlist and confirm the exporter leaves its source unchanged.

python tools/agent-operations/test_api.py
python tools/agent-operations/check_ui.py
python tools/agent-operations/check_edges.py

Start the reference server first. Browser checks need Node/npm and Playwright; no Codex account is required. Physical firmware installation and touch evidence are separate from browser verification.
