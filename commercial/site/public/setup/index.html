ONE COLLECTOR. ONE ADDRESS.

Bring your devices
into one view.

The collector owns the node registry. Its browser interface and API run on the same local server. Glimdock pairs once and receives the active nodes from it.

Start with the matching v0.5.6 packages

Download v0.5.6 and its checksums: matching Linux collector and device-agent packages for x86-64 and ARM64. Use current source builds for macOS and Windows. Choose the package for the machine’s OS and architecture. The central server runs on Linux or macOS; Windows machines send readings through the native agent.

You can also build from main using the build guide. v0.5.6 includes push enrollment and the integrated interface; v0.1.0 uses the earlier architecture.

  1. 1

    Start the central collector

    Choose an always-available Linux or macOS machine with network access to your devices. Install the matching collector or build it from source, then start it with glimdock-collector run --state-dir ./glimdock-state --bind 127.0.0.1 --port 8765. On that machine, open http://127.0.0.1:8765/; local access works directly. For LAN access, bind to the collector’s real LAN address and use the generated display key for readings and management key for node settings. You can include the collector host as a generic node or omit it.

    Commands, services and token setup
  2. 2

    Create a pairing key for your device

    Open Nodes → Add node → Pair a device. Choose a name and a collector address reachable from that machine, then create its one-time key. Save the key privately on the device. Platform detection and node identity are assigned during enrollment; you do not need a device feed URL.

    Native, SNMP and JSON API examples
  3. 3

    Let the agent send readings

    Use the command generated by the console and a matching binary on Windows, macOS or Linux. For example, on macOS/Linux: glimdock-agent --collector-url https://COLLECTOR:8765 --state-dir /ABSOLUTE/PRIVATE/agent --enrollment-key-file /ABSOLUTE/PRIVATE/enrollment.key. It pairs once, stores its identity and sends readings periodically. Delete the pairing file after success; keep its private state for future starts.

    SNMP and JSON adapters can collect from routers or APIs and push the same readings. Prefer HTTPS; trusted LAN HTTP requires explicit --allow-insecure-http. Devices need no incoming agent port. The collector does not scan the LAN or install agents on your devices.

    Rename, pause, resume or revoke agents in Nodes. To renew an existing pairing, stop the agent, create a fresh key for that node, then run once with --re-enroll and the same private state directory. Remove the recovery options after success. Existing polling nodes can switch to push while keeping their ID. Klipper/Moonraker, Proxmox feeds and other existing APIs can still be polled. Four top-level nodes and eight total nodes can be active; sixteen remote nodes can stay configured. Use optional parent_id grouping for managed switches and other children; their own source freshness is retained. Last receipt and measurement age remain distinct, so silent or stale devices lose current readings.

  4. 4

    Pair Glimdock once

    Connect USB-C power, join your 2.4 GHz Wi-Fi and save the collector snapshot address and display key in the display’s connection settings. Use the configuration key too if you want to manage nodes from its touchscreen. The address is http://COLLECTOR:8765/api/v1/snapshot; localhost on Glimdock would refer to the display itself.

    The display receives its node list from the collector. Start on All systems for summary bento cards, then tap a node for its detailed pages.

Use the browser as a display too.

Open Display & firmware in the collector. Its emulator runs the production firmware interface with your live nodes, at the same 320 × 240 resolution. Click or touch the canvas to navigate. The public website demo uses synthetic readings and cannot change your collector settings.

Update the firmware over USB.

  1. 1

    Open a supported browser

    Open the Glimdock USB installer in desktop Chrome or Edge. No local collector or companion is needed to flash from this website. You can also use Display & firmware in an HTTPS or localhost collector console.

  2. 2

    Connect the supported board

    Connect the Waveshare ESP32-S3-Touch-LCD-2.8 V1 with a USB data cable. Close any serial monitor holding the port. V2 firmware is not supported by this image set.

  3. 3

    Choose the port and install

    On the installer page, confirm the supported V1 board, choose Flash firmware and select the board’s serial port. The updater verifies the board and image hashes before writing and checks the programmed data afterwards. Saved Wi-Fi and collector pairing remain in their own flash partition.

Physical case validation is still in progress

The current fitted body uses the native board USB opening. Complete assembly and print validation are still in progress; keep the board and physical recovery buttons accessible during setup, and follow the current public enclosure guide before assembly.

Monitor agent systems too.

The portable agent-ops/v1 API and interactive browser preview cover task ownership, waiting states, queues, locks and reported usage. They are a native firmware workspace backed by a read-only Rust collector endpoint. Copy an integration prompt for your framework or collector.

New source features are separate from frozen release packages.v0.5.6 includes grouped subnodes, the native Agents workspace and matching firmware assets. Older v0.3.0 packages preserve their original feature set; use current source or v0.5.6 Linux packages for these improvements.

Choose the readings your devices expose.

Native OS values, hardware sensors, network interfaces and platform-specific APIs are all useful sources. A temperature or GPU reading may require device-specific support and permissions. The collector and display keep missing values unavailable and label stale data rather than inventing it.

Monitoring has no cloud account or subscription. Configuration keys grant access to node settings, so keep them private and keep the collector on your trusted network.
