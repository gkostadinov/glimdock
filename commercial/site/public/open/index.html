Install v0.5.4 or build from source

The v0.5.4 release includes matching Linux collector and device-agent packages for x86-64 and ARM64. macOS collectors and Windows device agents can be built from the current source. Choose the package for your OS and architecture and verify its checksum. This release includes push enrollment, the integrated web interface and browser firmware updates.

The current collector, agent, firmware and Pebble landscape source are on main. Download main source · Build it for your machine. The v0.1.0 downloads use the earlier architecture.

Know your board before you build.

The working firmware targets the Waveshare ESP32-S3-Touch-LCD-2.8 V1 with ST7789 display and CST328 touch, 16 MB flash and 8 MB PSRAM. V1 is discontinued. V2 uses a different touch controller; its driver and physical fit are not validated.

Pebble landscape is the current case conceptThe purple body and white USB base use serviceable covers and removable top accessories. Physical fit review is ongoing; full assembly, revised body printing and the continuous cradle remain physically unverified. The fitted body uses the native board USB opening. This revision is USB-powered. The firmware battery indicator does not establish a qualified battery product.

A central collector, a shared node registry.

Run one collector on Linux or macOS. Its host may be an ordinary server node, a Proxmox node on Linux, or omitted. Pair remote Rust agents with a one-time key; they receive a stable node identity and send readings without an incoming device port or feed URL. Add Moonraker and existing APIs as polling feeds. Names can change without changing identity. Up to four top-level nodes and eight nodes in total can be active, with sixteen remote nodes retained in configuration.

Windows is supported as a monitored device through the native Rust agent. The current central-server setup targets Linux and macOS. Devices expose what their hardware, APIs and permissions provide; temperatures and other hardware readings are optional.

The same firmware, in your browser.

The collector ships the production C++ interface and LVGL renderer compiled to WebAssembly. Every pixel is rendered at the display’s native 320 × 240 resolution. The public demo uses that same renderer with four synthetic devices; your installed collector uses your live node feeds.

Browser updates belong to your collector.

Chrome and Edge can write the public Waveshare V1 firmware over USB from the collector interface on HTTPS or localhost. Image hashes and board checks run before programming. The update preserves the saved Wi-Fi and collector pairing. Firmware source, relink material and license notices are supplied with the update bundle.

Monitor agent systems too.

The portable agent-ops/v1 API and interactive browser preview cover task ownership, waiting states, queues, locks and reported usage. They are a native firmware workspace backed by a read-only Rust collector endpoint. Copy an integration prompt for your framework or collector.

New source features are separate from frozen release packages.v0.5.4 includes grouped subnodes, the native Agents workspace, optional private conversation reader and matching firmware assets. Older v0.3.0 packages preserve their original feature set; use current source or v0.5.4 Linux packages for these improvements.

Open licenses, clear boundaries.

Original software is MIT. Original enclosure designs use CERN-OHL-P-2.0. Third-party firmware, fonts, libraries and tools retain their own licenses and notices. The bought-in display board is a separate manufacturer’s product.

Earlier releases stay available.

v0.1.0 is the earlier developer release, with Proxmox-first setup and the r7 enclosure. Use the current main source and its guides for push-agent enrollment, the integrated central collector and Pebble landscape design.

Help make the next version better.

Share your device model, board revision and sanitized logs when reporting a problem. Contributions to native probes, device APIs and tested enclosure fit are welcome.
